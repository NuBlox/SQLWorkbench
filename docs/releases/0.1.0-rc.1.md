# NuBlox SQL Workbench 0.1.0-rc.1

Release candidate for the first MySQL-focused NuBlox SQL Workbench desktop product path.

## Scope

This release candidate completes milestones M0 through M6 for MySQL:

- secure connection profiles and OS-backed credential encryption;
- SQL editor, execution, cancellation, history and result export;
- lazy database explorer and security metadata inspection;
- `@nublox/metaobject` reverse/forward engineering bridge;
- table, view and interactive ER schema engineering with guarded live DDL;
- query parsing, live catalogue completion, diagnostics, formatting, visual query building, explain-plan visualization and plan history/statistics;
- DBA administration for sessions, lock waits, variables/status, users/roles/privileges, storage, logical import/export, compare/transfer and backup-hook discovery.

## NuBlox package boundaries

The RC consumes independently published packages:

- `@nublox/mysql@3.1.0-rc.1`;
- `@nublox/metaobject@1.0.0-rc.1`.

SQL Workbench does not consume those projects through source-tree or Git commit coupling.

## Safety model

- renderer runs with context isolation, sandboxing and no Node integration;
- local renderer content is served through the privileged `nublox://` protocol with SvelteKit-generated CSP hashes;
- credentials are encrypted by the operating-system-backed Electron storage facility and are never persisted inside connection profiles;
- schema execution is previewed and stale-preview guarded;
- account GRANT/REVOKE changes use structured changes, validated MySQL accounts/privileges and exact confirmation phrases;
- direct data transfer requires `TRANSFER DATA` confirmation;
- table import/export uses native Electron file dialogs rather than renderer filesystem access;
- the RC does not expose kill-session operations;
- external `mysqldump` execution is disabled unless explicitly configured in a future release.

## Administration notes

Workbench JSON provides the RC's portable table-level logical backup/restore path. The MySQL provider also advertises an unavailable `mysqldump` hook so future full-database backup integration has a provider-neutral extension point without pretending a system binary is installed.

Table comparison in this RC compares row counts and column shape. It is not yet a row-by-row semantic diff engine.

## Desktop artifacts

The release workflow builds:

- macOS ZIP;
- Linux AppImage;
- Windows portable executable.

RC artifacts are not yet code-signed/notarized. Signing, notarization and installer polish are post-RC hardening activities.

## Requirements

- Node.js 22+ for source/development workflows;
- MySQL for the complete supported provider path.

## Validation

The release-candidate gate requires:

1. full monorepo `pnpm check`;
2. desktop package assembly verification in Linux CI;
3. cross-platform packaging on the RC tag;
4. GitHub prerelease artifact publication from the tagged commit.

## Deferred beyond this RC

- PostgreSQL provider;
- SQLite provider;
- SQL Server provider;
- Oracle provider;
- signed/notarized desktop distribution;
- configured external full-database backup executables;
- row-by-row semantic data diffing.
